Overview

Deterministic generation with explicit, bounded repair

The TypeScript compiler and repository evidence drive generation. Verification stays read-only. Repair is a separate opt-in mode with registered operations, provenance checks, exact-byte journaling, scope-aware reruns, and regression rollback.

How it works

From repository evidence to a verified artifact

Planning is deterministic and finalized before emission. The optional repair loop is isolated behind --repair and never changes production source or human-written tests.

1

Inspect

Repository Intelligence identifies compiler settings, framework mode, imports, exports, providers, render helpers, and existing-test evidence.

2

Build fixtures

Live TypeScript types produce deterministic structural fixtures. Required cycles, contradictions, and unsupported shapes are reported instead of guessed.

3

Plan and emit

A canonical behavioral plan is validated first. Each GENERATE scenario emits exactly one test; each SKIP emits none and is reported.

4

Protect and verify

Imports are revalidated and owned artifacts are written transactionally. Optional repair uses scope-aware Jest/Vitest runs and exact regression rollback.

Inference boundary - no model runs unless you pass a flag, and local Ollama is the default provider. Two opt-in paths exist. During repair, --repair --repair-llm lets local Ollama propose only registered operation IDs, never literal source edits; this path is restricted to exact loopback HTTP endpoints on port 11434, rejects redirects, and refuses any provider other than Ollama. During generation, --llm and --enhance let a model write or enhance test content, which is then revalidated before any write. Generation may target a cloud provider by setting TESTGEN_LLM_PROVIDER=anthropic|openai, which sends source code off-machine and is therefore denied by default: it requires TESTGEN_EGRESS_POLICY=allow, and the banking execution profile denies it unconditionally with no environment variable able to relax that. Cloud provider modules stay out of the CLI's static import graph, so a default run never loads them.
Features

What you get

>_

Structural type fixtures

Builds assignable values for primitives, objects, unions, tuples, callbacks, promises, records, generics, React types, and more from the live checker.

::

Trusted repair registry

Portable operation IDs own their schema, allowed issue types and scopes, prerequisites, mutation construction, safety, and verification blast radius.

TX

Transactional mutation

Content and provenance commit together. Interrupted writes are recovered from exact hashes, and conflicting bytes are handed off without mutation.

KB

Durable learning

The v2 knowledge base stores only portable registered operations and success evidence. Literal source edits stay in the per-run journal and are never promoted.

RTC

Requirement contracts

Local RTC drafting, schema checks, readiness scoring, immutable source snapshots, and approval hashes make ticket quality an explicit gate before generation.

RED

Frozen test evidence

Multi-signal mapping feeds a fail-closed RED phase. Frozen hashes, GREEN verification, mutation results, and traceability reports preserve the ticket-to-test chain.

Usage

Quick start

CLI 
# Install workspace dependencies
$ npm install

# Generate for one source file
$ npm run testgen:file -- src/components/Button.tsx

# Read-only: run the existing test exactly once
$ npx ts-node packages/testgen/src/cli.ts --file src/components/Button.tsx --verify

# Opt in to safe repair of a TestGen-owned generated test
$ npx ts-node packages/testgen/src/cli.ts --file src/components/Button.tsx --repair

# Also allow local Ollama registered-operation proposals
$ npx ts-node packages/testgen/src/cli.ts --file src/components/Button.tsx --repair --repair-llm

--verify never generates, repairs, or rewrites files. --repair-llm is invalid without --repair. Low coverage remains a separate result and never triggers repair generation.

ModeBehaviorMutation policy
GenerateAnalyze, plan, validate, and emit evidence-backed testsNew TestGen-owned generated test artifacts only
--verifyRun the existing Jest or Vitest test onceRead-only
--repairApply registered operations and verify at the correct scopeOwned generated tests/setup only; exact rollback on regression
--repair-llmAllow strict operation proposals from loopback OllamaNo literal edits; the same trusted registry executes every change
Ticket-driven pilot

Requirements are gated before code is generated

The experimental pilot path connects ticket evidence to an approved RTC, repository symbol mapping, a frozen RED artifact, GREEN verification, mutation testing, and a traceability report. Every uncertain boundary blocks or requires review instead of guessing.

A

Approve the contract

Revision and content hashes bind the RTC to its ticket snapshot. Non-approved, stale, or blocked contracts cannot enter the generation pipeline.

B

Map with evidence

Explicit references, call-graph, lexical, ownership, test-adjacency, semantic, and git-history signals contribute to a scored mapping decision.

C

Measure the pilot

Batch runs, ground-truth annotations, human-touch timing, and correlation reports support a blended Track A / Track B go-or-no-go decision.

Ticket-to-test pilot 
# Validate an approved requirement contract
$ npx ts-node packages/testgen/src/cli.ts rtc check --rtc .testgen/requirements/1234.rtc.yaml

# Map requirements, freeze RED tests, then verify GREEN
$ npx ts-node packages/testgen/src/cli.ts map --rtc .testgen/requirements/1234.rtc.yaml
$ npx ts-node packages/testgen/src/cli.ts red --rtc .testgen/requirements/1234.rtc.yaml --verify-red
$ npx ts-node packages/testgen/src/cli.ts green 1234

# Run the measured Phase 1 sample and produce correlation artifacts
$ npx ts-node packages/testgen/src/cli.ts pilot batch-run --dir tickets --steps A,B,C
$ npx ts-node packages/testgen/src/cli.ts pilot correlate

The Phase 1 batch and correlation commands are active development tooling, not a completed fleet rollout. Live ADO pilot execution, reviewed ground truth, and promotion thresholds remain external gates.
